# Resume Version Strategy

## Recommendation

Use **four resume versions** in the job-search platform:

1. **General / production default**
   - Public website and default PDF.
   - Balanced career story: enterprise IT → software engineering → CTO → global RPC/Solana/Web3 infrastructure → AI/platform systems.
   - Keeps the CTO/Hermes animation because it is a strong visual proof point, but copy frames it as applied R&D and architecture evidence rather than the whole identity.

2. **AI Infrastructure / Platform Leadership**
   - For Staff/Principal Platform, Head of Infra, AI Infra, agent platform, developer-platform, and SRE leadership roles.
   - Emphasize Kubernetes/GitOps, self-healing operations, Hermes/OpenClaw, MCP, model/provider routing, observability, secrets, and production debugging.

3. **Solana / Rust / Protocol Infrastructure**
   - For Solana ecosystem, protocol infrastructure, RPC, validator/node operations, Rust backend/platform, and Web3 infra leadership roles.
   - Emphasize Solana RPC, validator/node operations, global request scale, Rust/systems mindset, cost controls, reliability, incident response, and protocol-adjacent infra.
   - Avoid reading like a JavaScript/front-end or token/product profile.

4. **Fractional CTO / Consulting Proposal**
   - For consulting engagements, audits, infrastructure turnarounds, technical diligence, and platform modernization work.
   - Emphasize executive translation, scope shaping, team leadership, incident/cost reduction, architecture reviews, and delivery packages.

## Startup-risk critique

The current startup/project work is an asset and a risk.

### Asset signal

- Shows current hands-on relevance in AI infrastructure, Kubernetes, agents, model routing, MCP, and Rust/platform work.
- Differentiates from generic platform leaders who have not built with the current tooling wave.
- Provides strong visual proof through the CTO animation and concrete artifacts.

### Hiring-risk signal

Interviewers may infer:

- The candidate is primarily focused on his startup and may leave when it gains traction.
- The resume is over-indexed on a private/product agenda rather than the employer's needs.
- CTO/founder language may imply reluctance to operate inside another company's priorities.
- Too much project-specific terminology can obscure the broader 20+ year infrastructure career.

### Mitigation used in production default

- Keep CTO/Hermes as a visual/project proof point, not the headline identity.
- Frame 5D Labs as applied R&D and production-pattern evidence.
- Rebalance summary around the full career arc.
- Preserve enterprise IT, SRE, Head of Infra, CTO, Solana/RPC/Web3, and cost/reliability achievements.
- Add language that signals hands-on production debugging and employer-aligned operating judgment.

## Platform send policy

The job-search platform should attach versions by lane:

- **FT applications**: default to General; switch to AI Infrastructure or Solana/Rust when the posting clearly scores higher for that lane.
- **Consulting proposals**: default to Fractional CTO / Consulting.
- **Angel pitch decks**: do not use a resume as the primary outbound artifact; send pitch deck first, with resume/background link only as supporting context when useful.

## Version count guardrail

Do not create one resume per posting. Keep the matrix small:

- 1 default public resume
- 3 targeted variants

Tailoring should happen in the intro/cover/proposal first; resume variant only changes when the role category changes.
